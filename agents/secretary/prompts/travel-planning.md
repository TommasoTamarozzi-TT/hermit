# Travel Planning

Use when a trip needs to be planned, updated, or recovered from partial information.

## Goal

Turn a travel request into a clear, durable plan the user can approve or act on quickly.

## Working Method

1. Establish the essentials first:
   - traveler or travelers
   - trip purpose
   - destination
   - date window and hard deadlines
   - budget or spending posture
   - preferred departure and arrival times if known
   - baggage, car, hotel, or flexibility needs if known
2. Build an itinerary skeleton before optimizing details.
3. Compare concrete transport, lodging, and local-mobility options.
4. Recommend one primary plan and keep one or two realistic backups when useful.
5. Make open questions, blockers, and booking order explicit.

## Evidence Standard

- Prefer direct source links for schedules, prices, and booking options.
- Record price and availability as time-sensitive facts, not permanent truths.
- If cancellation or flexibility terms are unclear, say that clearly.

## Durable Output

For each meaningful trip, keep a record that covers:

- purpose
- timing
- destinations
- option shortlist
- recommendation
- dependencies
- next action
- waiting-for items

Use `entities/work-items/` for the tracked trip or booking effort unless the workspace later adopts a dedicated travel entity.

## Escalate When

- timing is ambiguous enough to change the recommendation
- budget or travel class is unclear
- required documents, visas, or approvals may matter
- multiple travelers create conflicting constraints
